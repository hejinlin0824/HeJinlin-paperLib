# V3.1 论文理解质量升级

## 输入与覆盖策略
- 正文按 section/block 读取，不再在固定 5,200 字符处静默截断。
- 长 block 按句子/段落切分为有界 chunk；每个 chunk 保留原始 block_id。
- 分块分析覆盖全部可分析正文，逐块 checkpoint；失败块会计入失败数，档案明确标记不完整。
- 超长 chunk-note 汇总按完整 JSON 对象分批压缩，不切开 JSON 字符串或证据引文。

## 理论逻辑
- theory_logic 支持多前提超边，尤其 JOINTLY_SUFFICIENT_FOR。
- 联合充分关系必须有至少两个来源节点，不能拆成单个条件分别充分。
- 理论逻辑单独回填并使用专门验证提示，验证状态与“证据已定位”分开显示。

## 知识角色
贡献节点可标注 knowledge_role：
- formal_definition：正式定义
- operational_criterion：操作判据
- example_or_case：案例或反例
- non_essential_property：明确声明的非必要属性
- proof_or_argument：证明或论证
- core_claim：核心主张
- background：背景

## 覆盖指标
payload.coverage 包含章节数、chunk 总数/完成数/失败数、正文块数、原文字符数、实际送入模型的字符数、input_coverage 和 complete。覆盖率只描述输入覆盖，不等价于语义理解正确率。

## 安全边界
V3.1 继续复用隔离的 kg_understanding_drafts 草稿表。不会写入或迁移 V2 的 kg_entities、kg_relations、kg_evidence。旧草稿保留，V3.1 新任务使用版本号 3.1。
