# 知识图谱数据纳入与测试隔离

## 论文纳入分类

每篇论文有一个 `papers.library_role` 字段：

| 值 | 含义 | 是否进入科研知识图谱 |
|---|---|---|
| `normal` | 正常科研文献（默认） | 是 |
| `test` | 测试、fixture、mock 或演示数据 | 否 |
| `excluded` | 用户主动排除的其他论文 | 否 |

旧数据库升级时，已有论文统一迁移为 `normal`，不会根据标题猜测或自动删除。
如果发现测试论文混入图谱，在“科研知识地图 → 论文纳入范围”中将其改为“测试数据”或“其他排除项”。原始 PDF、正文块、阅读记录和证据行都保留；图谱查询视图会立即按新分类过滤。

后端也提供接口：

```http
PATCH /api/knowledge-graph/papers/{paper_id}/scope
Content-Type: application/json

{"library_role": "test"}
```

允许值：`normal`、`test`、`excluded`。该接口只修改分类，不执行删除。

## 统一可见性规则

所有面向用户的图谱查询使用 `kg_visible_evidence`、`kg_visible_relations`、`kg_visible_entities` 和 `kg_visible_jobs` 视图。统计、搜索、全局关系、单篇结构、主题、证据和任务列表遵循同一规则。

关系的 evidence_type 和 confidence 由“当前可见论文”的证据重新聚合。测试论文即使曾经提高过同一条共享关系的全局评分，也不能影响正常论文用户看到的关系类别和评分。

## 测试数据库隔离

`tests/conftest.py` 为每个 pytest 用例自动创建独立临时 SQLite 数据库，并将后端 DB_PATH 指向该文件。测试结束后由 pytest 清理临时目录。测试不应连接或修改 `data/library.db`。

## 存量数据审计

默认只读预览：

```bash
python tools/audit_knowledge_graph.py
```

可指定数据库：

```bash
python tools/audit_knowledge_graph.py --db path/to/library.db
```

脚本会按标题中的 test、mock、fixture、demo、测试、示例等线索标出“待人工确认”的候选项；这些只是提示，不是自动判定。

只有明确确认某篇论文后，才对指定 ID 执行分类：

```bash
python tools/audit_knowledge_graph.py --set-role PAPER_ID test
```

脚本不提供批量自动删除，也不删除论文、块、关系或证据。需要恢复纳入时将 role 改为 `normal`。
