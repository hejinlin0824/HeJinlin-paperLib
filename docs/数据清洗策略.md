# PDF 正文数据清洗策略

## 目标

清洗对象是解析器把出版模板和 PDF 排版残留误当成正文的情况，而不是对论文内容做语义改写。典型噪声包括 arXiv 编号/水印、期刊或会议状态行、版权/DOI 页边信息、重复页眉页脚，以及页底脚注。

原则是：**只自动删除高置信噪声；对不确定的内容优先保留；每次清理都提供可追溯记录。** 不按单个关键词全局删文，避免误伤正文里正常讨论 arXiv、期刊或引用格式的句子。

## 多层清洗流程

1. **解析前的 PDF 版面信号（内置 PyMuPDF 引擎）**：利用页号、文本块坐标、字号与脚注标记识别页面顶部/底部的小字。若同一页出现有明确脚注标记的小字号页底块，从脚注起始区域清掉脚注，不把它拼接到前后的正文段落。
2. **行级水印清理**：在正文块形成前，独立识别 arXiv:2401.01234v2 [cs.CV] 2 Feb 2024 这一类整行编号、Preprint submitted to ...、Published as a conference paper at ... 等模板状态行。若水印和摘要位于同一文本块，只剔除那一行，保留其他正文行。
3. **块级脚注识别**：过滤明确的 sup 数字脚注块、Corresponding author 等标签，以及带脚注标记并包含邮箱、通讯作者、资助信息等特征的块。不会因为一个段落以普通编号开头就删除它；例如 “1 Introduction” 不是脚注。
4. **跨页页眉/页脚识别**：对页码、ACM 风格的 263:3、作者缩写页脚和重复短文本做归一化。通用重复文本规则要求至少在 **3 个不同页面**出现，且文本长度达到下限；不会只因为一个短词反复出现就删除。
5. **双解析引擎统一后处理**：内置解析器和 MinerU 输出进入同一套高置信清理，再进行作者卡、章节切分和翻译调度。翻译器不负责猜哪些论文内容应该删掉——正文应在送入翻译之前先被清理。
6. **可追溯报告**：清理规则、计数和最多 12 条样本保存在每篇论文的 cleaning_report 中。阅读器会展示清理数量，并允许展开查看被删掉的样本；这样可以发现规则误判并继续补充回归测试。

## 保守边界

- 对独立且格式明确的 arXiv 水印自动删除；正文句子中普通提及 arXiv 不会按关键词过滤。
- 对内置引擎，脚注主要使用坐标、字号与标记组合识别；对 MinerU，坐标信息通常不完整，因此使用明确脚注标签、语义标记和跨页重复线索。
- 矢量图、扫描版脚注、被 OCR 完全改写的水印以及与正文混在同一行但没有明显标记的内容可能仍需人工检查。无法可靠区分时应保留原文，而不是误删。
- 重解析时先保留旧块；只有新解析成功并通过非空检查后，才在数据库事务中替换旧块。失败时旧译文仍然可读。
- 清理报告样本不是全文审计日志，不会把整篇被删文本大量复制到数据库。

## 清理已有论文

新规则会应用到后续上传/重解析的论文。已经存入数据库的旧块不会自动改变，避免程序升级后静默破坏用户已有批注。

先预览：

    python tools/clean_paper.py
    # 或只检查一篇
    python tools/clean_paper.py PAPER_ID

确认输出后再应用；脚本会先用 SQLite backup API 将数据库一致性备份到项目根目录的 backups/，然后才更新论文块：

    python tools/clean_paper.py --apply PAPER_ID
    # 全部论文（先预览，再决定是否应用）
    python tools/clean_paper.py --apply

被批注引用的噪声块会保留为不显示正文的占位块，尽可能维持批注的块 ID；章节索引会在清理后重建。运行前仍建议关闭 PaperLib，避免清理脚本与阅读器同时写入 SQLite。
