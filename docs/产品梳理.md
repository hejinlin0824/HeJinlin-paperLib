# 论文图书馆（Paper Library）· 产品梳理 v0.1

> 定稿日期：2026-10-26 ｜ 状态：已确认核心决策，待评审后进入开发
> 本文档是产品的"需求宪法"，后续开发以本文档为准，变更需在此记录。

---

## 0. 一句话定位

**本地优先的个人科研阅读工作站**：上传论文 PDF → AI 翻译成排版一一对应的中文 → 沉浸式双语精读与批注 → 沉淀为结构化的研究总表和个人知识库。

它不是又一个"翻译工具"，而是：翻译是入口，批注是过程，**总表和知识库才是沉淀**。

## 1. 为什么现有产品不够用（我们的差异化）

| 现有方案 | 痛点 | 我们的做法 |
|---|---|---|
| 沉浸式翻译 / 知云 / CopyTranslator | 机翻生硬、术语不一致；不可批注；不管读后记录 | AI 灵活翻译 + 术语表一致性 + 批注 + 阅读记录一体 |
| Zotero + 插件 | 管理强但翻译弱，批注留在 PDF 上，无科研视角的读后结构化 | 原生"研究问题/方案/创新点/我的思考"结构 |
| ReadPaper / 知乎学术 | 云端产品，数据不在自己手里，笔记体系固定不可定制 | 全部数据本地，一个文件夹拷走即迁移备份 |

## 2. 已确认的核心决策（2026-10-26 与用户对齐）

| 决策点 | 结论 |
|---|---|
| 产品形态 | **本地 Web 应用**：本机跑一个服务，浏览器访问 localhost；全部数据本地 |
| 翻译引擎 | **云端 API 优先**（用户电脑较弱，跑不动本地 Ollama）；架构上用 OpenAI 兼容协议抽象，未来可无缝切本地 Ollama |
| PDF 解析引擎 | 云端解析优先（同上理由），本地 MinerU 作为可选引擎，接口抽象可插拔 |
| 阅读形态 | **全都要**：① 逐段双语对照 ② 中文为主、点击段落看原文 ③ 纯英文、点击看翻译 ④ 原版 PDF 并排 ⑤ 图表/公式侧边导航 |
| MVP 范围 | **批注 + 研究总表一起做**：上传→解析→翻译→全模式阅读→批注体系→研究总表，一期全部打通；知识库二期 |

## 3. 核心用户流程（Happy Path）

```
拖入 PDF
  → 自动解析（图表、公式LaTeX、表格、参考文献，云端引擎）
  → 分段 AI 翻译（进度条实时可见，术语表保证全文一致）
  → 进入阅读器（中/英/对照三种模式随时切换，原PDF并排核对）
  → 精读：选中文字→高亮/加粗/写批注/记问题；段落→重译/编辑译文/写小结
  → 读完自动进入研究总表，补全：研究问题/解决方案/创新点/我的思考/评分
  → 问题进入问题追踪，解决了勾掉，形成成长记录
  → （二期）知识库聚合全部批注/小结/问题，全文搜索，跨论文检索
```

## 4. 功能模块

### M1 文献入库与解析
- 拖拽/选择上传 PDF；自动抽取元数据（标题/作者/年份/来源/DOI）
- 解析引擎可插拔：云端解析（默认，弱机友好）/ 本地 MinerU（离线可选）
- 产出统一的结构化块序列（见 §7 数据模型），图片存本地、公式保 LaTeX、表格保结构、参考文献单独抽取
- 解析状态与失败重试

### M2 AI 翻译引擎
- OpenAI 兼容协议统一抽象：DeepSeek / GLM / Kimi / OpenAI /（未来 Ollama）一个配置切换
- 段落级翻译：只翻文本块，公式/图/表结构原样保留 → **排版一一对应**
- 术语表机制：术语 en→zh 注入每段 prompt，保证全文一致；可人工维护
- 上下文注入：每段携带论文标题+摘要，翻译更贴题
- 并发调度 + 结果缓存（按段哈希幂等，重试不浪费钱）+ WebSocket 实时进度
- 单段可重译、译文可人工编辑修正
- 成本量级：DeepSeek/GLM Flash 级模型翻一篇 10 页论文约几分钱到几毛钱（以官网价格为准）

### M3 阅读器与批注（核心体验）
- **三种正文模式全局切换 + 段落级点击互换**：纯中文（点击段落→看原文）/ 纯英文（点击段落→看翻译）/ 双语逐段对照
- **原版 PDF 并排**开关（PDF.js 渲染，与译文按页锚点联动滚动）
- 侧边导航栏：目录大纲 / **图表公式导航**（点击跳转）/ 本篇批注列表 / 参考文献
- 选中文字浮动工具条：**高亮（多色）/ 加粗 / 写批注 / 记问题**（问题直接进问题追踪）/ 复制
- 段落操作：重译本段 / 编辑译文 / 写段落小结
- 引用标记 [n] 悬浮显示参考文献条目
- 阅读进度记忆（回到上次位置）
- 批注锚定：锚在"块 id + 锚文本"上，重译后批注不丢（字符偏移变了也能按锚文本找回）

### M4 研究总表（科研成长记录）
- 大表格视图，每篇论文一行，列：论文（标题/作者/年份/来源）、标签、**研究问题、解决方案、创新点/可借鉴、我的思考、一句话收获**、评分、问题（未解决数）、状态（在读/读完/搁置）、最后阅读时间
- 行内快速编辑 + 详情弹窗编辑（长文本）；与阅读器一键互跳
- 筛选（标签/状态/有无未解决问题）、排序、搜索
- 导出：CSV / Excel / Markdown（方便写开题、综述时引用）

### M5 知识库（二期）
- 聚合全部批注/高亮/小结/问题，全文搜索
- 按论文/标签/时间/类型过滤；批注卡片可回跳原文位置
- 问题看板：未解决 / 已解决，记录解决过程
- （三期）跨论文 RAG 问答："我的文献库里关于 XX 的观点有哪些"

### M6 设置与数据管理
- 翻译/解析引擎配置：API Key、Base URL、模型选择、并发数、一键测试连接
- 术语表管理（增删改、导入导出）
- 数据备份：整个 `data/` 目录打包导出/恢复；单篇论文导出（双语 MD + 图片 + 批注）

## 6. 技术架构

```
┌─────────────────────────────────────────────────────┐
│ 浏览器 SPA（Vue 3 + TypeScript + Vite）              │
│  · 阅读器：块级渲染组件 + KaTeX 公式 + PDF.js 并排    │
│  · localhost:8300（生产模式下由后端直接伺服静态文件）   │
└──────────────────────┬──────────────────────────────┘
                       │ HTTP + WebSocket
┌──────────────────────▼──────────────────────────────┐
│ 本地后端 FastAPI（Python，单进程单端口）               │
│  ├─ routers: papers / translate / annotations /      │
│  │           log(总表) / questions / settings        │
│  ├─ 解析服务（可插拔）：云端解析 API │ 本地 MinerU     │
│  │    PDF → 结构化块（图/LaTeX公式/表格/参考文献）      │
│  ├─ 翻译调度器：分段 → prompt组装(术语表+上下文)        │
│  │    → 并发调用 → 缓存 → WS进度推送                   │
│  │    引擎抽象：OpenAI 兼容协议                        │
│  │    ├─ 云端：DeepSeek / GLM / Kimi / OpenAI …       │
│  │    └─ 未来：Ollama（本机 11434，同协议，零改造）     │
│  └─ 存储：SQLite（library.db）+ 文件库（data/）        │
└──────────────────────┬──────────────────────────────┘
                       │
        data/（整个目录拷走 = 完整备份迁移）
         ├─ library.db
         └─ papers/{id}/ original.pdf · blocks.json · meta.json · assets/（图片）

启动方式：双击 启动.bat → 起后端 → 自动打开浏览器
```

**选型理由**
- 后端选 Python/FastAPI：最好的 PDF 解析生态（MinerU、PyMuPDF）都在 Python；FastAPI 轻、自带异步、WS 方便
- 引擎全部走 OpenAI 兼容协议抽象：今天接云端，明天想本地化换 Ollama 只改配置不改代码
- SQLite + 本地文件：单机单人零运维；无账号无鉴权（只监听 localhost）
- 前端 Vue3 + Vite：轻快；阅读器是块级组件渲染（不是纯 markdown 渲染），才能做段落级双语切换与批注锚定

**目录规划**
```
论文图书馆/
├─ backend/app/        # FastAPI：routers / services / db
├─ frontend/           # Vue3 + Vite
├─ data/               # 用户数据（git 忽略）
├─ docs/               # 本文档及后续设计文档
└─ 启动.bat
```

## 7. 数据模型（核心表）

```
papers        id, title, title_zh, authors, year, venue, doi,
              status(parsed/translating/ready/failed), tags,
              rating, reading_progress, created_at, updated_at

blocks        id, paper_id, order_idx,
              type(heading/text/formula/image/table/list/citation),
              en, zh, meta(laTeX/图片路径/表格结构/标题层级),
              translate_status          ← 排版一一对应的基石

annotations   id, paper_id, block_id,
              kind(highlight/bold/note/summary/question),
              anchor_text, anchor_range, color, content,
              created_at, updated_at    ← 锚定块id+锚文本，重译不丢

research_log  paper_id(主键), research_problem, solution,
              innovation, my_thoughts, takeaway, status, updated_at

questions     id, paper_id, content, answer, status(open/resolved),
              created_at, resolved_at

glossary      id, term_en, term_zh, note, source(manual/auto)

settings      key, value（引擎配置等）
```

## 8. 关键难点与对策

| 难点 | 对策 |
|---|---|
| PDF 解析质量（双栏/公式/表格/扫描件） | 云端专业解析引擎为主；阅读器保留原 PDF 并排随时核对；解析失败可换引擎重试 |
| 翻译"机翻感"、术语不一致 | 学术翻译 prompt + 术语表注入 + 论文上下文注入；单段重译 + 译文人工可编辑 |
| 批注在重译后错位 | 锚定块 id + 锚文本，偏移变了按锚文本模糊找回 |
| 弱电脑性能 | 解析与翻译全在云端，本机只做调度与伺服；SQLite 零负担 |
| 公式渲染 | KaTeX 渲染 LaTeX；渲染失败兜底显示解析时的公式截图 |
| 引用对应 | 解析时抽取参考文献列表，正文 [n] 悬浮显示 |

## 9. 分期计划

**一期（MVP，含批注+总表）**
1. 项目骨架：FastAPI + Vue3 + SQLite + 启动脚本
2. M1 上传与解析（云端引擎，统一块结构）
3. M2 翻译管线（并发/缓存/进度/术语表）
4. M3 阅读器：三模式 + PDF并排 + 侧边导航 + 高亮/加粗/批注/问题/小结 + 重译与译文编辑
5. M4 研究总表 + 问题追踪 + 导出 CSV/MD
6. P1/P2/P6 基础版（工作台/论文库/设置）

**二期**
- P5 知识库（聚合/搜索/问题看板）、术语表管理页、数据备份恢复、单篇导出（双语MD+批注）

**三期**
- 本地 Ollama 引擎接入（配置级切换）、Zotero/BibTeX 导入、跨论文 RAG 问答、双语排版 PDF 导出
