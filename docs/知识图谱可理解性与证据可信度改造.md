# 知识图谱可理解性与证据可信度改造

## 目标

PaperLib 的知识图谱服务对象首先是科研阅读者，而不是图数据库工程师。用户要回答的是：

1. 这篇论文研究什么问题、提出什么方法、使用什么数据/模型、报告了什么结果？
2. 两个知识点为什么被系统认为有关？原文哪句话支持？
3. 这是论文明确说的，还是模型推测出来的？
4. 哪些关系值得继续阅读，哪些需要人工核验？

因此，节点和连线数量、布局美观程度不能代替可理解性和证据可信度。

## 调研依据

- Li et al., *Knowledge Graphs in Practice: Characterizing their Users, Challenges, and Visualization Opportunities*, IEEE TVCG 30(1), 2024, DOI: 10.1109/TVCG.2023.3326904. 对 19 位知识图谱实践者的访谈指出，Builder、Analyst、Consumer 的需求不同；普通 node-link 图对消费者的解释力不足，知识卡片、时间线、渐进式探索和 AI 预测语义解释值得优先考虑。
- Huang et al., *Making graph visualization a user-centered process*, Journal of Visual Languages & Computing, 2018, DOI: 10.1016/j.jvlc.2018.07.001. 强调图可视化应按用户任务评价，并采用 overview、zoom、filter、details-on-demand 等交互。
- Nečaský & Stenchlák, *Interactive and iterative visual exploration of knowledge graphs based on shareable and reusable visual configurations*, Journal of Web Semantics, 2022, DOI: 10.1016/j.websem.2022.100713. 提倡用领域化、可复用的视图配置隐藏与当前任务无关的图结构复杂度。
- Bludau et al., *Unfolding Edges: Adding Context to Edges in Multivariate Graph Visualization*, EuroVis / Computer Graphics Forum, 2023. 强调边本身的属性和证据上下文是用户正确理解关系、建立信任的关键。
- Sigma.js lifecycle 文档说明 Graphology 数据变更会触发处理和重绘；画布必须有非零尺寸。Sigma refresh 应用于状态变化，而非用频繁重建图来替代交互状态管理。

## 产品决策

### 1. 证据优先，而不是连线优先

关系探索默认展示「证据清单」，每条关系直接呈现：

- 起点实体；
- 关系谓词；
- 终点实体；
- 来源论文和章节；
- 可读的原文证据摘录；
- 点击后打开关系详情与原文定位。

关系图降级为可选的结构探索视图。图用于发现结构，证据清单用于理解和核验事实。

### 2. 明确区分三类证据

| 类型 | 含义 | 默认行为 |
|---|---|---|
| explicit | 论文原文直接表达该关系，且摘录能定位回原文 | 默认展示 |
| inferred | 模型根据上下文推断，原文没有直接表达 | 默认隐藏，按需开启；不当作事实 |
| similarity | 语义相似或主题接近，不代表因果、继承或技术改进 | 默认隐藏，按需开启 |

抽取提示词升级为 v2：抽取阶段只允许输出原文明示关系。即使模型提供了一段逐字存在的引文，也不意味着引文一定蕴含它声称的关系；因此 schema 层同样拒绝 inferred/similarity 关系进入新抽取结果。

旧数据中的 inferred/similarity 不会被删除；用户仍可显式打开查看。重新抽取采用现有的按论文事务化替换流程，不自动在后台触发，以避免未经确认产生模型调用费用。

### 3. 关系摘要必须与现存证据一致

关系表上的 evidence_type/confidence 是派生摘要，不应永久保留历史最高值。每篇论文重抽取并替换证据后，重新从当前存活的证据行计算关系类型和最高模型评分，避免原文证据已撤销、关系却仍显示为 explicit 的问题。

模型自报 confidence 不是经过校准的统计概率，因此不在用户主视图中显示为「可信度百分比」。用户应查看原文证据、来源论文和人工核验结果。

### 4. 渐进式探索

- 总览：展示纳入论文、已抽取论文、实体和关系覆盖情况。
- 主题：只展示明确抽取出的研究领域；共享数据集作为实验资源交集，不能冒充研究主题。
- 证据清单：默认入口，适合阅读、比较和核验。
- 关系图：可选入口，支持类型、关系和证据类型筛选；点击边/节点查看详情。

## 当前实现范围

- 启动前只读核验 data/library.db 与 data/papers/，防止数据库缺失/空库而论文文件仍存在时误启动。
- 关系图 API 默认只返回 explicit 关系；通过 evidence_types 参数显式请求 inferred/similarity。
- 新版抽取 prompt/schema 只接受 explicit 关系。
- 每次按论文替换证据后，重算关系级 evidence_type 和 confidence。
- 关系查询返回证据摘录、章节和来源论文 ID。
- 关系探索默认使用证据清单，图谱作为可选视图。
- 新增关系人工审核状态：待核验、人工已确认、已驳回；驳回只改变展示状态，不删除关系和原文证据；可切换显示已驳回项并恢复待核验。

## 尚需继续验证

1. 用用户真实数据库执行只读盘点，确认论文记录、PDF 文件数量和数据库路径是否一致。
2. 对历史抽取结果做离线审计：关系是否确实被证据句蕴含，而不只是证据句包含实体名。
3. 人工审核目前记录状态，但尚未记录 reviewer、时间和理由；后续可补充审计轨迹。
4. 用真实多论文数据做任务测试：能否在 30 秒内回答「某方法由哪篇论文提出」「哪个数据集被哪些论文使用」「某关系的原文证据在哪里」。
5. 在真实浏览器验证列表/图视图切换、筛选、证据跳转、空数据状态和窗口缩放。
