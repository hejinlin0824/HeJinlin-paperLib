# 知识图谱 V3：先理解论文，再建模

## 目标与安全边界

V2 的按章抽取会把章节中的名词与局部关系合并，容易将背景、相关工作、实验配置误当成核心贡献。V3 将“论文理解”作为独立前置产物：

1. 章节角色识别与章节摘要；
2. 全文综合，形成论文理解档案；
3. 贡献树分层（core / supporting / context）；
4. 只在贡献树节点之间提出少量候选关系；
5. 对每条关系执行独立语义蕴含核验；
6. 人工审阅、修订、确认或驳回。

**隔离保证：** V3 只写入 `kg_understanding_drafts`。不写入、不更新、不删除 `kg_entities`、`kg_relations`、`kg_evidence`，也不会自动触发 V2 抽取。用户确认理解档案目前只代表认可理解结果，不代表已导入正式图谱。

## 论文理解档案

核心字段：
- `paper_type`：theory / algorithm / system / empirical / survey / other；
- `problem`、`thesis`：核心问题与中心主张；
- `contributions`：贡献树节点，含 id、kind、importance、parent_id、evidence；
- `theoretical_framework`：定义、假设、条件、命题、定理、引理、证明等；
- `method_architecture`：算法/系统模块；
- `key_findings`：关键发现；
- `limitations`、`uncertainties`：局限与不确定项；
- `section_map`：章节角色和摘要；
- `relations`：贡献树内部的候选关系及语义验证状态。

理论论文应重点保留 Definition、Assumption、Condition、Proposition、Theorem、Lemma、Corollary、Proof 等结构。算法论文重点识别问题、算法、模块、目标函数、复杂度和实验结论；系统论文重点识别架构、组件、数据流和设计约束。提示词允许按论文类型适配，不再强制所有论文使用一套扁平实体清单。

## 证据和关系验证

- 每个重要贡献必须带来源 block_id 和逐字 quote。
- 服务端再次验证 quote 是否逐字存在于对应块；无法定位的节点/关系会被移除并写入 warnings。
- 关系候选只能连接贡献树中已有节点。
- 独立 verifier 输出 entailed / not_entailed / uncertain；验证失败时按 uncertain 处理。
- “在 CIFAR-10 上评估”不能支持“改进 CIFAR-10”；共现、引用和相似性不能自动升级为因果、提出或继承关系。
- verifier 仍是模型判断，不是形式化证明；用户应优先检查原文证据和逻辑方向。

## 使用方式

1. 启动 PaperLib，打开 `http://127.0.0.1:8300/kg-understanding`。
2. 选择已解析论文，点击“生成理解档案”。
3. 等待章节分析、全文综合和关系核验完成，点击刷新结果。
4. 审查论文类型、核心问题、贡献树、理论结构、候选关系和原文证据。
5. 可编辑页面下方 JSON，点击保存；确认或驳回只改变草稿状态。
6. 现有图谱保持不变。不要期待 v3 确认后立即改变旧图谱节点/边数量。

## 成本与范围

一次运行通常包含每个有效章节一次摘要调用、一次全文综合调用、一次关系候选生成调用，以及每条候选关系一次 verifier 调用。长论文/章节较多时会产生多次模型请求。请先选 Harness 等代表论文单篇试跑，不要批量运行全库。

当前版本的输入受章节与全文字符预算限制；超过预算的文本可能未进入综合上下文。系统不会伪造缺失证据，但可能漏掉位于未覆盖内容中的贡献。若论文特别长或理论结构复杂，应结合原文核对，并把不确定项保留下来。
